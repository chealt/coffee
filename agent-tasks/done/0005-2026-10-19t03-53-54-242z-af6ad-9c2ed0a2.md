## Root cause

Roaster 265 (Pikola) had the webshop URL `https://www.kafepikola.pl/doporucujeme` stored in the data. The shop restructured
its site and that page now returns 404 (verified with `curl`), so `recordRoasterWebshop` failed at the
`response.ok` check and threw `Failed to fetch webshop page`. The current coffee listing page is
`https://www.kafepikola.pl/kawa` (confirmed via the shop's `sitemap-categories.xml.gz`). The page markup there is
unchanged (`article.card-item[data-href]` with coffee links ending in `-espresso`/`-filtr`/`-omni`), so both the
webshop-processor and webshop-item-processor parsers for roaster 265 keep working without changes.

## Fix

Updated the webshop URL for roaster 265 from `https://www.kafepikola.pl/doporucujeme` to
`https://www.kafepikola.pl/kawa` in `packages/coffee.chealt.com/data/roasters.json`,
`roastersBest.json` and `roastersWithCoffees.json`, following the precedent of commit fd675b82
("manual data export, update pikola webshop url"). Note: the roasters table in the production database still needs
the same URL update by a maintainer so the next automated data export doesn't overwrite this.
