## Root cause

Error-scan false positive, same class as tasks 0007/0010 — not a production failure. The line is a
benign `INFO` log from the Kolo Coffee parser (roaster 296,
`packages/webshop-item-processor/src/parsers.js`, `Missing origin region: ${regionText}`). For
`https://kolocoffee.eu/products/panama-bambito-estate` the parser correctly identifies the origin
country as Panama (`originCountryId: 16`), but no region in `data/originRegions.json` matches: the
product title, tags (`Filter Coffee`, `New`) and description only name the farm ("Bambito
Estate"), and Panama's known regions are `bajo mono`, `boquet`, `boquete`, `volcan` and
`volcan baru national park`. Storing `originRegionId: null` for such data gaps is by design — the
item is still recorded with price, weight, image, taste notes and varieties populated.

The scan only flagged it because the description contains "exceptional" (twice), which the old
`ERROR_PATTERN` (`(?i)(error|exception|unhandled|timed out|fail)`) matched as the substring
`exception`.

## Fix

No code change needed: the word-boundary fix for `ERROR_PATTERN` is already on main
(`0c06f5a2` "fix(0007)" and `57c0af1c` "fix(0010)"), so this signature — and the other
"exceptional" INFO signatures — can no longer be created by future scans. The parser works as
intended; hard-coding a region it cannot derive from the page would be wrong.

Optional maintainer follow-up (out of scope): add a Panama region for the Bambito farm area
(Renacimiento district, Chiriquí) to the production database if region-level data for this coffee
is wanted.
