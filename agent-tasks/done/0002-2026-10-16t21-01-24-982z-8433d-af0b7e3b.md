## Root cause

Sister task 0003 (same log events) shows the underlying cause: `TypeError: fetch failed` with
`[cause]: Error: certificate has expired` (`code: 'CERT_HAS_EXPIRED'`). On 2026-10-16 sercekawy.pl
served an expired TLS certificate, so every `fetch` from the `flagRemoved` Lambda failed TLS
verification. undici wraps this as a generic `TypeError: fetch failed`, and the handler's catch
block logged only `error.message`, producing the opaque `Fetch failed for <url> with error: fetch failed`
lines (88 occurrences). The roaster renewed the cert on 2026-10-17 (current chain: CN=www.sercekawy.pl,
issued by Shoper DV TLS G2 R34 CA, valid to 2027-05-04); fetches succeed again. No coffee was wrongly
flagged as removed — the handler correctly returns without flagging on fetch failure.

Reproduced locally: ran an HTTPS server with an expired (self-signed) certificate and called `fetch`
with the handler's exact options (`redirect: 'manual'`, undici `Agent` dispatcher) — undici throws
`fetch failed` with `cause.code === 'CERT_HAS_EXPIRED'`, and the old catch block logged exactly this
task's signature with the cause invisible.

## Fix

`packages/flag-removed/src/index.js`:

- Log the undici cause (`error.cause.code` / `error.cause.message`) in the failure message, so future
  occurrences read e.g. `Fetch failed for <url> with error: fetch failed (CERT_HAS_EXPIRED)` instead of
  the generic message.
- Corrected `connectTimeout` from `10 * 1000 * 1000` (10,000 s) to `10 * 1000`, matching its
  "10 seconds" comment.

Verified: repro server now yields a log line including `(CERT_HAS_EXPIRED)`; live fetches of the
affected sercekawy.pl URLs return 200 with the new timeout; `yarn lint` passes. The workspace test
script (`yarn workspace @centralbeans/flag-removed test`) is a live integration script requiring AWS
secrets (`.env`) and could not be run in this environment.
