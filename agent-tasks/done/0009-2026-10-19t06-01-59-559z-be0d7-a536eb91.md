## Root cause and fix

**Root cause:** migacoffee.pl (Shopify) serves product images with protocol-relative URLs (`//migacoffee.pl/cdn/shop/files/...`). The webshop-item-processor parser for Miga Coffee (roaster 13, `packages/webshop-item-processor/src/parsers.js`) read `.product__media img`'s `src` and passed it through unmodified. Since the parser builds the DOM with `new JSDOM(html)` (base `about:blank`), the protocol-relative value is returned verbatim, and the downstream `recordWebshopItemDetails` lambda fails at `fetch(url)` with `TypeError: Failed to parse URL from //...` (Node's fetch requires an absolute URL).

**Reproduction:** the live `https://migacoffee.pl/products/brazil-espresso` page contains `src="//migacoffee.pl/cdn/shop/files/BRAZYLIA_d7e3a66b-8dd0-46ec-ac59-5aa230010ebb.png?v=1770902194&width=1946"`; `fetch()` on that value throws the exact error from the log.

**Fix:** prefix the protocol-relative `src` with `https:` in the Miga parser (same pattern already used by other Shopify parsers in the file; identical to the parallel fix for task 0008 on `origin/task/0008`, so the branches merge cleanly). Verified with `ROASTER_ID=13 yarn workspace @centralbeans/webshop-item-processor test`: `brazil-espresso` now parses with `image: 'https://migacoffee.pl/cdn/shop/files/BRAZYLIA_d7e3a66b-8dd0-46ec-ac59-5aa230010ebb.png?v=1770902194&width=1946'`, which returns HTTP 200 (`image/png`).

**Out of scope (pre-existing, unrelated):** several other Miga products fail at `weightOption.value` (parsers.js:1098) because the weight selector markup changed; that's a separate parser bug, not this error signature.
