## Root cause and fix note (2026-10-23)

- **Root cause:** The Miga Coffee (roaster 13) item parser in `packages/webshop-item-processor/src/parsers.js:1098` read `.value` off `weightOption` without a null guard. Its fallback selector `variant-selects input[name^="waga-1"]` is case-sensitive on the attribute value, and Miga started naming the option `Waga` (capitalized) on newer products, rendering radios with `name="Waga-1"`. Neither selector matched, `weightOption` was `null`, and the handler crashed with `TypeError: Cannot read properties of null (reading 'value')`.
- **Reproduction:** `ROASTER_ID=13 yarn workspace @centralbeans/webshop-item-processor test` — 11 of 17 products (e.g. `colombia-cauca`, `nicaragua-las-diosas`, `peru-cajamarca`) failed with the exact production stack (`parsers.js:1098:33`).
- **Fix:** Minimal one-line change — added the CSS case-insensitivity flag to the fallback selector: `variant-selects input[name^="waga-1" i]`, which matches both `waga-1` and `Waga-1` radios. Verified all 17 Miga products now parse with valid weights/prices.
- **Note:** The `Missing weight` entry in the logs (from the default Shopify parser at `parsers.js:107`) is a handled business error thrown for variant titles without a weight, not the crash behind this signature.
