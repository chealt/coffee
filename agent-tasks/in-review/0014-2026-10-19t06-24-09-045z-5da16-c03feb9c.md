## Root cause and fix

**Root cause:** Prolog's "Advent Calendar 2026 - Curiosity Edition" (`https://www.prologcoffee.com/products/pre-order-advent-calendar-2026-curiosity-edition`) is a pre-order gift set — a box of 4×125g coffees — not a regular coffee product. Its only variant is titled "Default Title" with no weight, so `parseVariantWeight` returns `undefined` in the Prolog parser (roaster 1, `packages/webshop-item-processor/src/parsers.js`) and it throws `Missing weight`. The product is tagged "coffee" / type "Coffee beans" on Shopify, so the webshop list processor cannot filter it out by type; it is the only Prolog product without `125g`/`250g`/`1000g` weight variants.

**Reproduction:** saved HTML via `ROASTER_ID=1 node packages/webshop-item-processor/save-html.js`, then `ROASTER_ID=1 yarn workspace @centralbeans/webshop-item-processor test` logs the exact error: `No weight found for https://www.prologcoffee.com/products/pre-order-advent-calendar-2026-curiosity-edition`.

**Fix:** treat advent calendar products as gift sets in the Prolog item parser — when the product title contains "advent calendar", return `{ isGiftSet: true }` (same pattern used by other roasters' parsers for boxes/gift sets, e.g. roaster 39's "zestaw prezentowy"). The handler already skips gift sets gracefully. Verified with `ROASTER_ID=1 yarn workspace @centralbeans/webshop-item-processor test`: the advent calendar is now skipped (`Skipping advent calendar gift set ...`) and all 14 remaining Prolog products process without errors. `yarn lint` and `yarn format` pass.
